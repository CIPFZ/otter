# M1 验收报告

- 日期：2026-10-16
- 分支：`feat/m1-playback`
- 关联：SPEC §19、§21；ADR-003

## 结论

**M1 尚未完全验收。** 「真机矩阵至少在一台 iPhone 与一台 Android 上实际跑过」这一条没有满足：没有可用的手机端点。其余各项都已完成，见下表。

| SPEC §21 M1 验收项 | 状态 | 证据 |
|---|---|---|
| 全场景矩阵能播（M1 范围） | ✅ 桌面 Chrome / Firefox / Safari、模拟 Android / iPhone、真机 Windows Edge | 下文各表；HEVC 场景在无 HEVC 解码的环境按预期优雅失败（WebCodecs / WASM 在 M4） |
| iPhone MMS 条件自动处理 | ⚠️ 已实现；单测 + WebKit「仅 MMS」模拟在 CI 通过；**未在真 iPhone 上验证** | `backend-mse` MMS / AirPlay 处理、`e2e/playback.spec.ts` MMS-only 用例 |
| stats 面板有数据 | ✅ | 截图；e2e 断言面板与 store 一致 |
| `router.explain()` 可导出选路决策 | ✅ | stats 面板的 Route 区块；每个 e2e 用例附 `state.json` |
| 真机矩阵：至少一台 iPhone 与一台 Android | ❌ 未完成 | 需要设备端点（`e2e/README.md`） |

## M1 中发现并修复的问题

见 RESEARCH §1「M1 实测发现的坑」和 ADR-003「实现中补充」。其中只在真实浏览器 / 真机上才暴露的有：HEVC 时 hls.js 加载挂起、Windows Edge 上手动切档不生效、LL-HLS 慢网下档位未知、`<otter-stats hidden>` 仍然显示。
