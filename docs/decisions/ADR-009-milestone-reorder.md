# ADR-009：里程碑重排：自研 CMAF-HLS 引擎提前到 M5，真机回归移至最后（M7）

- 状态：已采纳
- 日期：2026-10-20
- 关联：`SPEC.md` §19、§21；`AGENT.md` §2.6、§2.7；ADR-004（部分修订）；ADR-006

## 背景

原 SPEC §21 的顺序是 M4 → M5（弹幕、水印、DASH 优化）→ M5.5（移动端真机回归）→ M6（自研 CMAF-HLS 引擎、presets、框架绑定、SSR、文档站）。M3 验收后项目负责人提出两点：

1. 自研引擎是核心开发任务，与弹幕之间没有技术依赖，没有理由排在最后。它只依赖 M3 已有的 fMP4 remuxer 与 MSE sink，M4 之后即可开始。
2. 真机回归验的应该是最终代码。如果回归之后 M6 再替换 HLS 播放路径，M5.5 验过的 HLS 结果就作废，需要重验。

原 M6 把「自研引擎」和「发布打包」两类性质不同的工作混在一起，是最初按「先功能、后体积与发布」排序的结果，不是技术约束。

## 决定

| 新编号 | 内容 | 来源 |
|---|---|---|
| M4 | 不变 | — |
| M5 | 自研轻量 CMAF-HLS 引擎替换简单场景；音视频分离 DASH 优化、多编码探测与偏好持久化；`danmaku`、水印 | 原 M6 的引擎部分 + 原 M5 全部 |
| M6 | presets 发布、体积收口；`ui-skin-tv`、shorts preset、React/Vue/Svelte 绑定、SSR、文档站 | 原 M6 去掉引擎部分 |
| M7 | 移动端与 TV 真机回归：M1–M6 全部场景与模式 | 原 M5.5，移至最后 |

配套调整：

- 验收：M5 增加「自研引擎在 §19 短视频 / 长视频点播场景替换 hls.js 后 TTFF 与 rebuffer 不劣于适配器，含引擎口径简单点播 < 30KB」；M6 验收改为「体积预算全部达标（含 Hero < 5KB）；文档站上线」；M7 验收与原 M5.5 相同，范围扩为 M1–M6。
- 体积口径（修订 ADR-004）：自有代码列门禁范围由 M1–M5 改为 M1–M6；含引擎列由「M6 前只记录」改为「M5 自研引擎落地起对短视频 / 长视频点播场景门禁，M6 全部门禁」。Hero < 5KB 的例外与回归哨兵不变，M6 起门禁。
- 真机口径（修订 ADR-004）：桌面真机 + CI WebKit + 模拟移动端的要求覆盖 M1–M6；真 iPhone / Android / TV 在 M7 一次性补跑。ADR-004 正文保留原文，在状态行注明被本 ADR 修订。
- 所有文档中的「M5.5」引用改为 M7：SPEC §21（含 M1 行）、AGENT §2.6、ADR-006 §代价。历史报告（`docs/reports/M1.md` 等）不改。

## 代价

- 真机问题暴露得更晚：iPhone MMS、伪全屏、横屏锁、Android 硬解差异要到 M7 才集中验证，返工范围从 M1–M5 扩大到 M1–M6。缓解办法不变：WebKit 的「仅 MMS」与触控模拟用例持续保留在 CI；presentation 严格按 RESEARCH §1 与 SPEC §15 坑表实现。
- M5 的工作量变大（自研引擎 + 弹幕），执行时按批次拆分：引擎先于弹幕，引擎批次单独汇报。
- 自研引擎提前意味着 Q3（与 SPF 的关系）必须在 M5 开始前结案，由项目负责人在 M4 收尾时决定。
