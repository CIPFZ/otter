# Otter 0.1.0-beta.0

The first beta of Otter, the pluggable web video player. Every published `@otter-player/*` package
is at `0.1.0-beta.0` and is published under the npm dist-tag `beta` (`npm install
@otter-player/presets@beta`). 1.0 follows the real-device regression (M7); until then only betas are
published, and the API may still change between betas.

## What is in it

- **Ten scenario presets** (`@otter-player/presets/<id>`): `basic`, `vod`, `live`, `lowlatency`,
  `ott-drm`, `surveillance`, `danmaku`, `shorts`, `tv`, `background`, and `createPlayer` for your
  own composition. Each sub-path carries only its scenario's formats and backends.
- **Formats and engines:** HLS on Otter's own CMAF-HLS engine with hls.js for what it hands over
  and Shaka for DRM; DASH on Shaka; HTTP-FLV / WS-FLV and live MPEG-TS on Otter's own pipeline with
  mpegts.js as the fallback; progressive MP4 with Range requests; WebRTC WHEP; local files.
- **Backends:** MSE (and ManagedMediaSource), native `<video>`, and WebCodecs (GPU canvas, a
  shared decode pool, an AudioWorklet clock; decoders a host adds, e.g. WASM, plug in).
- **Player UI:** `otter-*` Web Components with three skins (`ui-skin-default`, `-minimal`, `-tv`;
  CSS only), English and Chinese texts, keyboard, pointer, gesture and TV remote input, captions
  (WebVTT, SRT, IMSC1 / TTML, CEA-608) with user styles, presentation modes (theater, fullscreen,
  PiP, Document Picture-in-Picture, mini window, background), electronic zoom and picture filters.
- **Danmaku (scrolling comments)** on Canvas 2D, WebGL or a Worker, with masks; watermarks.
- **Framework bindings:** `@otter-player/react`, `@otter-player/vue`, `@otter-player/svelte`, all
  server-render safe.
- **CDN:** `@otter-player/cdn` serves `presets/basic` and `presets/vod` as ES modules for pages
  without a build step, through jsDelivr:
  `https://cdn.jsdelivr.net/npm/@otter-player/cdn@0.1.0-beta.0/dist/otter-vod/otter-vod.esm.js`
  (and `otter-vod.css`; `otter-basic` likewise).
- **Docs** generated from the sources (`pnpm docs:serve` in the repository).

## Browser baseline

Chrome / Edge 110+, Firefox 115+, Safari 16.4+, iOS Safari 16.4+. Below the baseline there are no
polyfills: the native backend plays what the browser can.

## Not published in this beta

Placeholders stay private: `plugin-analytics`, `plugin-cast`, `plugin-p2p`, `plugin-record`,
`plugin-screenshot`, `overlay-ads`, `text-ass`, `ui-skin-audio`, `decoder-wasm-ffmpeg`, and
`decoder-wasm-hevc` (GPL content, see the known limitations).

## Known limitations

- **Not verified on real phones and TVs yet.** iPhone, Android phones and Tizen / webOS TVs are
  covered by emulation in CI only; the real-device regression is milestone M7. On iPhone in
  particular: system fullscreen shows only the `<video>`, HLS goes native where
  ManagedMediaSource is missing, and frame-accurate seeking is unconfirmed.
- **WebCodecs audio path: an occasional short silence (audio underrun) under load.** Seen once, on
  Chromium's Android emulation with a file source; the decode queue was not backed up; the cause
  is not found yet (RESEARCH §1, F16). (The underruns on live MPEG-TS walls in several browsers
  had another cause, fixed in this beta.)
- **No WASM HEVC decoder ships with Otter.** The builds available (Jessibuca's, FFmpeg inside) are
  GPL, which the published packages do not carry. Without HEVC hardware decoding a surveillance
  tile with an HEVC stream reports the non-fatal `hevcDecoderUnavailable` and does not play; a host
  can pass its own decoder in the `decoders` option of `createSurveillancePlayer`.
- **WHEP: the browser stretches time.** WebRTC's jitter buffer, owned by the browser, inserts or
  removes samples and changes the playback speed without concealment (in Chrome about 95–300 ms
  every 20 s locally). The player does not compensate: latency estimates from the receiver's
  `currentTime`, or sync with other sources, are affected.
- **Real Windows Firefox: an occasional first frame of about 10 s** on the WebCodecs path (all
  transports); cause not found.
- **Colour on WebKit and Windows Edge:** these platforms colour-manage `<video>` but not the
  WebCodecs canvas, so the same stream looks slightly different in a surveillance wall and in a
  single `<video>` (a red bar: 248, 36, 0 against 254, 0, 0).
- **Safari, paused seek on `<video>`** may stop on an earlier frame without repainting. For frame
  accuracy use the WebCodecs path (`format-file` with `backend-webcodecs`).
- **Surveillance walls:** browsers allow 6 HTTP/1.1 connections per host, so more than 6 HTTP-FLV /
  TS tiles from one host need WS-FLV or HTTP/2 (each tile past the sixth reports
  `tooManyConnectionsPerHost`). FLV / TS on WebCodecs play live streams only (`live: false` goes
  through MSE).
- **Danmaku masks on Safari:** WebKit decodes no VP9 alpha, so WebM masks are rejected there; use
  SVG masks. The moving watermark resists page scripts and extensions, not whole-page capture
  tools.
